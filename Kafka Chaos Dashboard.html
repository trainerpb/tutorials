Local Dev Topology (KRaft + Toxiproxy)

To establish a resilient testing architecture as described in the "Kafka Deep Dive" file, we use two separate configuration files to isolate the KRaft cluster from the proxy layer.

1. The Kafka Core

The docker-compose -kafka.yml file explicitly provisions a fixed cluster ID to avoid boot synchronization failures[cite: 1]. It configures distinct internal and external routing ports: INTERNAL://0.0.0.0:29092 for intra-docker UI communication and EXTERNAL://0.0.0.0:9092 for external proxies or clients[cite: 1]. The Kafka UI is exposed on port 9080[cite: 1].

2. The Chaos Proxy

The docker-compose.yml file provisions the Toxiproxy daemon (exposing the management API on 8474 and a proxy port on 19092) alongside the buckle/toxiproxy-frontend UI dashboard on port 8080[cite: 2]. The UI container is directed to talk to the backend over the docker network using TOXIPROXY_URL=http://toxiproxy:8474[cite: 2].

Routing Instruction: Configure Toxiproxy to listen on port 19092 and forward upstream to host.docker.internal:9092. Then, configure your Spring Boot application to bootstrap to localhost:19092.

Native ProducerRecord Sender

Bypassing standard templates to inject custom native headers using ProducerRecord.

import org.apache.kafka.clients.producer.ProducerRecord;
import org.springframework.kafka.core.KafkaTemplate;
import org.springframework.stereotype.Service;
import java.nio.charset.StandardCharsets;

@Service
public class NativeHeaderProducer {

    private final KafkaTemplate<String, Object> kafkaTemplate;

    public NativeHeaderProducer(KafkaTemplate<String, Object> kafkaTemplate) {
        this.kafkaTemplate = kafkaTemplate;
    }

    public void sendWithNativeRecord(String topic, String key, Object payload) {
        // Construct the native Kafka record
        ProducerRecord<String, Object> record = new ProducerRecord<>(topic, key, payload);
        
        // Append raw byte[] headers for tracing and chaos metadata
        record.headers().add("X-Trace-ID", "trace-5541".getBytes(StandardCharsets.UTF_8));
        record.headers().add("X-Tenant", "tenant-alpha".getBytes(StandardCharsets.UTF_8));

        // Fire and rely on application.yml for delivery.timeout.ms resolution
        kafkaTemplate.send(record).whenComplete((result, ex) -> {
            if (ex != null) {
                System.err.println("Delivery completely failed: " + ex.getMessage());
            }
        });
    }
}

Native ConsumerRecord Listener

Receiving the full record allows extraction of metadata, partition info, and native headers alongside the deserialized payload.

import org.apache.kafka.clients.consumer.ConsumerRecord;
import org.apache.kafka.common.header.Header;
import org.springframework.kafka.annotation.KafkaListener;
import org.springframework.stereotype.Service;
import java.nio.charset.StandardCharsets;

@Service
public class NativeHeaderConsumer {

    @KafkaListener(topics = "lab-topic", groupId = "chaos-group")
    public void consume(ConsumerRecord<String, Object> record) {
        System.out.printf("Received on Partition: %d | Offset: %d | Key: %s%n", 
                          record.partition(), record.offset(), record.key());
        
        // Extract native headers safely
        Header traceHeader = record.headers().lastHeader("X-Trace-ID");
        if (traceHeader != null) {
            String traceId = new String(traceHeader.value(), StandardCharsets.UTF_8);
            System.out.println("Processing Trace Context: " + traceId);
        }

        // Process automatically deserialized payload
        Object businessData = record.value();
        System.out.println("Payload: " + businessData.toString());
    }
}
