1. Compute Foundation Recap: Physical CPU vs. Virtual CPU (vCPU)

🖥️ Physical CPU vs. vCPU

A CPU is the physical silicon processor installed on a data center server motherboard. A vCPU (Virtual CPU) is a logical, time-sliced execution thread scheduled by a hypervisor (such as KVM) and exposed to your guest VM.

⚡ 1 Server Core = How Many Client vCPUs?

Modern enterprise server processors utilize Simultaneous Multithreading (SMT / Intel Hyper-Threading), splitting 1 physical processor core into 2 independent hardware execution threads. Thus, in GCP, 1 physical server core = 2 vCPUs.

2. Cloud Storage Levels & Why It Is Called a "Bucket"

Cloud storage is divided into three architectural levels: File Storage (hierarchical network folders like Filestore), Block Storage (raw low-latency volumes like Persistent Disks used for VM boot drives and databases), and Object Storage (Google Cloud Storage).

🪣 What is a Bucket & What Can It Store?

A Bucket is the top-level root container in Google Cloud Storage used to hold unstructured binary objects of any format (up to 5 TB per single object)—including images, 4K videos, CSV datasets, database backups, and compiled Spring Boot .jar files.

📂 Why Called a "Bucket" Instead of a "Folder"?

Traditional file systems use nested hierarchical directory trees where renaming a top folder requires updating every child path. Object storage uses a single flat namespace—like tossing millions of items into one giant bucket. "Folders" seen in the UI (e.g., images/2026/logo.png) are simply visual illusions created by `/` characters in the object's string key!

📍 Regional Bucket

Data is replicated across multiple zones within a single region (e.g., us-central1). Lowest cost; best when co-located with Compute Engine VMs or GKE clusters to eliminate cross-region network latency.

🌍 Dual-Region Bucket

Data is replicated across a specific pair of regions (e.g., us-central1 + us-east1). Offers high availability and optional Turbo Replication (15-minute RPO) for disaster recovery.

🌐 Multi-Region Bucket

Data is distributed across a large continental area (e.g., US, EU, ASIA). Offers 99.95%–99.99% availability SLA; ideal for serving public static assets to distributed end users.

All GCS storage classes provide 99.999999999% (11 9s) annual durability and millisecond first-byte latency. They differ in monthly storage price, minimum storage duration, and per-GB retrieval fees:

2. Object Metadata & Built-In Caching (Cache-Control)

Every GCS object consists of raw binary data plus key-value Metadata. Metadata is divided into Fixed-Key Metadata (HTTP headers & system properties) and Custom Metadata (x-goog-meta-* user-defined tags):

🏷️ Real-Life Enterprise Metadata Use Cases

  • Data Lake & ETL Filtering: Tagging raw files with source-system=CRM and schema-version=v2 so Dataflow jobs filter objects without reading file payloads.
  • Automated Content Moderation: Setting moderation-status=pending on user uploads until a Cloud Vision webhook updates it to approved.
  • Browser Rendering Control: Setting Content-Type: application/pdf or text/plain so browsers render files inline instead of downloading raw binary streams.

⚡ Caching in GCS (Cache-Control & Rapid Cache)

  • HTTP Edge Caching: Publicly readable objects default to Cache-Control: public, max-age=3600, caching assets in browsers and Cloud CDN for 1 hour to slash egress billing. For dynamic config files, set Cache-Control: no-cache, no-store.
  • Rapid Cache (Anywhere Cache): An SSD-backed zonal read cache inside GCP data centers that accelerates bursty AI/ML training reads from multi-region buckets.

3. Object Versioning: Problem, Solution & Generation Mechanics

🚨 The Problem

Cloud Storage objects are immutable. Overwriting backup.sql with a corrupted 0-byte file or accidentally running rm permanently destroys the original data in a standard bucket.

🛡️ The Solution

Enable Object Versioning on the bucket. When an object is overwritten or deleted, GCS keeps the old copy as a noncurrent version identified by a 16-digit generation number.

🔍 Live vs. Noncurrent Check

The current (live) version has time_deleted = null (absent in CLI output). A noncurrent version has a populated time_deleted timestamp and requires #generation to access.

1. Bucket-Level CLI Commands & Removing a Non-Empty Bucket

How to Delete a Non-Empty Bucket vs. an Empty Bucket:
• gcloud storage buckets delete gs://my-bucket FAILS if the bucket contains any objects or noncurrent versions (safety check).
• gcloud storage rm --recursive gs://my-bucket (or -r) deletes all objects, all versions, and the bucket itself in one fast parallel operation!
• gcloud storage rm "gs://my-bucket/**" deletes all objects inside the bucket while keeping the empty bucket intact.

Module 4: Bucket IP Filter Lockout Troubleshooting & IAM Architecture

Why 0.0.0.0/0 Locks You Out on IPv6 Networks, Break-Glass IAM Recovery, and Service Account vs. Owner

IPv4 vs IPv6 Lockout exemptFromIpFilter Least Privilege IAM

1. Why Applying 0.0.0.0/0 to a Bucket IP Filter Causes "Access Denied"

When you enable GCS Bucket IP Filtering and allow only 0.0.0.0/0, you expect the bucket to be open to all networks. Instead, both the GCP Console and CLI immediately block you with: Access denied due to either IP filtering or VPC configuration. Here is why:

1️⃣ IPv6 Routing Exclusion

0.0.0.0/0 only matches 32-bit IPv4 addresses. Modern broadband ISPs and mobile 5G hotspots route Google traffic over 128-bit IPv6 by default. Without ::/0 in your allowed list, every IPv6 packet from your machine is rejected!

2️⃣ Internal VPC Routing

Requests originating from Compute Engine VMs, Cloud Run, or GKE inside a GCP VPC travel over Google's internal network rather than the public internet, so they ignore publicNetworkSource rules unless the VPC is explicitly listed.

3️⃣ Blocked Service Agents

Enabling IP filtering blocks internal Google Cloud service agents unless allowAllServiceAgentAccess: true is explicitly set in the filter configuration.

2. Step-by-Step Break-Glass Rescue Procedure (When Locked Out of Your Bucket)

If even gcloud storage buckets update gs://BUCKET --clear-ip-filter fails with Access Denied because your ISP/hotspot uses IPv6, you must grant yourself the project-level storage.buckets.exemptFromIpFilter permission via a custom IAM role:

BASH — BREAK-GLASS IAM ROLE CREATION & IP FILTER REMOVAL 
# STEP 1: Create a Custom IAM Role containing the IP Filter Exemption permission
gcloud iam roles create ip_filter_recovery \
    --project="ivory-link-511508-u3" \
    --title="IP Filter Recovery" \
    --permissions="storage.buckets.exemptFromIpFilter" \
    --stage="GA"

# STEP 2: Bind the Custom Recovery Role to Your Google Account at the Project Level
gcloud projects add-iam-policy-binding "ivory-link-511508-u3" \
    --member="user:sohamsironline@gmail.com" \
    --role="projects/ivory-link-511508-u3/roles/ip_filter_recovery"

# STEP 3: Wait ~2 minutes for global IAM caching to propagate, then wipe the IP filter!
gcloud storage buckets update gs://soham-sg-test --clear-ip-filter

3. IAM Architecture: Service Account vs. Owner Role

Dimension Service Account (Identity — "WHO") Owner / roles/owner (Role — "WHAT")
Architectural Category A non-human machine Principal / Identity used by VMs, Cloud Run services, and Spring Boot apps to authenticate API calls. A legacy primitive IAM Role (collection of thousands of permissions) granting unrestricted administrative control over a project.
How It Works Authenticates via short-lived OAuth tokens, Attached VM Metadata, or cryptographic JSON keys rather than browser passwords. Can be assigned to a human user, a Google Group, or a Service Account. Allows modifying billing and deleting any resource.
Security Best Practice Assign narrow predefined roles (e.g., roles/storage.objectAdmin on a single bucket) rather than project-wide primitive roles. Never grant roles/owner to a Service Account! If its JSON key leaks on GitHub, attackers gain full control of your cloud project.

JAVA — CRUD, CUSTOM METADATA, LIVE VS NONCURRENT VERSION CHECK & RESTORE 
import com.google.cloud.storage.*;
import java.nio.charset.StandardCharsets;
import java.util.Map;

public class GcsPlainJavaMaster {

    public static void main(String[] args) {
        // 1. Auto-discover local ADC credentials (from 'gcloud auth application-default login')
        Storage storage = StorageOptions.getDefaultInstance().getService();

        String bucketName = "soham-sg-test";
        String objectName = "architecture-notes.txt";

        // 2. Enable Object Versioning on the Bucket
        Bucket bucket = storage.get(bucketName);
        bucket.toBuilder().setVersioningEnabled(true).build().update();

        // 3. Create (Upload) Version 1 with Fixed & Custom Metadata
        BlobId blobId = BlobId.of(bucketName, objectName);
        BlobInfo blobInfoV1 = BlobInfo.newBuilder(blobId)
                .setContentType("text/plain")
                .setCacheControl("no-cache")
                .setMetadata(Map.of("author", "Prof-Soham", "module", "Cloud-Storage", "env", "dev"))
                .build();

        Blob v1 = storage.create(blobInfoV1, "Version 1 Content: Initial Draft".getBytes(StandardCharsets.UTF_8));
        System.out.println("Uploaded V1 Generation: " + v1.getGeneration());

        // 4. Overwrite with Version 2 (V1 automatically becomes NONCURRENT)
        Blob v2 = storage.create(blobInfoV1, "Version 2 Content: Updated Final".getBytes(StandardCharsets.UTF_8));
        System.out.println("Uploaded V2 (Live) Generation: " + v2.getGeneration());

        // 5. Read the Current Live Version
        byte[] liveBytes = storage.readAllBytes(blobId);
        System.out.println("Current Live Payload: " + new String(liveBytes, StandardCharsets.UTF_8));

        // 6. List All Generations and Identify CURRENT (Live) vs NONCURRENT
        Iterable<Blob> allVersions = storage.list(
                bucketName,
                Storage.BlobListOption.prefix(objectName),
                Storage.BlobListOption.versions(true) // Crucial: includes archived generations
        ).iterateAll();

        long archivedGenToRestore = 0L;
        for (Blob b : allVersions) {
            if (b.getName().equals(objectName)) {
                // If getDeleteTimeOffsetDateTime() is null, it is the LIVE version!
                boolean isLive = (b.getDeleteTimeOffsetDateTime() == null);
                System.out.println((isLive ? "[LIVE CURRENT] " : "[NONCURRENT]   ")
                        + "Gen: " + b.getGeneration() + " | Custom Meta: " + b.getMetadata());
                if (!isLive) {
                    archivedGenToRestore = b.getGeneration();
                }
            }
        }

        // 7. Restore Noncurrent Version back to Live via CopyRequest
        if (archivedGenToRestore != 0L) {
            BlobId historicalSource = BlobId.of(bucketName, objectName, archivedGenToRestore);
            storage.copy(Storage.CopyRequest.newBuilder()
                    .setSource(historicalSource)
                    .setTarget(blobId)
                    .build());
            System.out.println("Restored generation " + archivedGenToRestore + " as the new live object!");
        }
    }
}

2. Complete Spring Boot Service: 5 Real-World Enterprise Use Cases

Below is a production-ready Spring Boot @Service and @RestController demonstrating all five core patterns: (1) Spring Resource / WritableResource streaming, (2) Multipart file upload with custom metadata & Cache-Control, (3) V4 Signed URLs for temporary private downloads, (4) Object version listing & rollback, and (5) Safe conditional creation (doesNotExist):

JAVA — GcsEnterpriseStorageService.java (5 USE CASES) 
package com.soham.cloud.storage;

import com.google.cloud.storage.*;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.core.io.Resource;
import org.springframework.core.io.WritableResource;
import org.springframework.stereotype.Service;
import org.springframework.web.multipart.MultipartFile;

import java.io.IOException;
import java.io.InputStream;
import java.io.OutputStream;
import java.net.URL;
import java.nio.charset.StandardCharsets;
import java.util.*;
import java.util.concurrent.TimeUnit;

@Service
public class GcsEnterpriseStorageService {

    private final Storage storage;

    @Value("${app.gcs.bucket-name}")
    private String bucketName;

    // USE CASE 1: Direct gs:// Resource Injection
    @Value("gs://${app.gcs.bucket-name}/sample-text.txt")
    private Resource gcsBannerResource;

    public GcsEnterpriseStorageService(Storage storage) {
        this.storage = storage;
    }

    // --- USE CASE 1A: Read Cloud Object via Spring Resource Abstraction ---
    public String readViaSpringResource() throws IOException {
        try (InputStream is = gcsBannerResource.getInputStream()) {
            return new String(is.readAllBytes(), StandardCharsets.UTF_8);
        }
    }

    // --- USE CASE 1B: Write Cloud Object via Spring WritableResource ---
    public void writeViaSpringResource(String text) throws IOException {
        WritableResource writable = (WritableResource) gcsBannerResource;
        try (OutputStream os = writable.getOutputStream()) {
            os.write(text.getBytes(StandardCharsets.UTF_8));
        }
    }

    // --- USE CASE 2: Multipart Upload with Custom Metadata & Cache-Control ---
    public Map<String, Object> uploadMultipartWithMetadata(
            MultipartFile file, String uploadedBy, String category) throws IOException {

        BlobId blobId = BlobId.of(bucketName, file.getOriginalFilename());

        Map<String, String> customMeta = new HashMap<>();
        customMeta.put("uploadedBy", uploadedBy);
        customMeta.put("category", category);
        customMeta.put("moderationStatus", "pending");

        BlobInfo blobInfo = BlobInfo.newBuilder(blobId)
                .setContentType(file.getContentType())
                .setCacheControl("public, max-age=3600") // Cache at CDN/Browser for 1 hour
                .setMetadata(customMeta)
                .build();

        Blob created = storage.create(blobInfo, file.getBytes());
        return Map.of(
                "name", created.getName(),
                "generation", created.getGeneration(),
                "md5", created.getMd5ToHexString(),
                "metadata", created.getMetadata()
        );
    }

    // --- USE CASE 3: Generate V4 Signed URL for Temporary Private Access ---
    public String generateSignedDownloadUrl(String objectName, int expiryMinutes) {
        BlobInfo blobInfo = BlobInfo.newBuilder(BlobId.of(bucketName, objectName)).build();
        URL signedUrl = storage.signUrl(
                blobInfo,
                expiryMinutes,
                TimeUnit.MINUTES,
                Storage.SignUrlOption.withV4Signature()
        );
        return signedUrl.toString();
    }

    // --- USE CASE 4: Inspect All Object Versions (Live vs Noncurrent) & Rollback ---
    public List<Map<String, Object>> listObjectVersions(String objectName) {
        List<Map<String, Object>> result = new ArrayList<>();
        Iterable<Blob> blobs = storage.list(
                bucketName,
                Storage.BlobListOption.prefix(objectName),
                Storage.BlobListOption.versions(true)
        ).iterateAll();

        for (Blob b : blobs) {
            if (b.getName().equals(objectName)) {
                boolean isCurrentLive = (b.getDeleteTimeOffsetDateTime() == null);
                result.add(Map.of(
                        "generation", b.getGeneration(),
                        "status", isCurrentLive ? "CURRENT_LIVE" : "NONCURRENT_ARCHIVED",
                        "sizeBytes", b.getSize(),
                        "updatedAt", String.valueOf(b.getUpdateTimeOffsetDateTime())
                ));
            }
        }
        return result;
    }

    public void rollbackToGeneration(String objectName, long generationId) {
        BlobId oldVersion = BlobId.of(bucketName, objectName, generationId);
        BlobId liveTarget = BlobId.of(bucketName, objectName);
        storage.copy(Storage.CopyRequest.newBuilder()
                .setSource(oldVersion)
                .setTarget(liveTarget)
                .build());
    }

    // --- USE CASE 5: Safe Atomic Upload (Prevent Accidental Overwrite) ---
    public void createOnlyIfAbsent(String objectName, String content) {
        BlobInfo info = BlobInfo.newBuilder(bucketName, objectName).setContentType("text/plain").build();
        // Throws StorageException (412 Precondition Failed) if object already exists!
        storage.create(info, content.getBytes(StandardCharsets.UTF_8), Storage.BlobTargetOption.doesNotExist());
    }
}
