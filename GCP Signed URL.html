Module 1: Step-by-Step URL Signing Lab via gcloud CLI, IAM & Service Account Keys

Configuring Service Accounts, Impersonation vs. JSON Keys, Credential Storage Locations, and Production Guardrails

GOOG4-RSA-SHA256 Service Account IAM Key Storage Security

1. Architectural Concept: Why Signed URLs Need a Service Account

A V4 Signed URL acts as a cryptographic "valet key" that delegates temporary access to a single private object in Google Cloud Storage without making the bucket public. Because the link must be signed with an RSA private key (GOOG4-RSA-SHA256), standard human user credentials (sohamsironline@gmail.com) cannot sign URLs directly. Instead, you must use a Service Account via one of two mechanisms:

✅ Approach A: Keyless Service Account Impersonation (Production Standard)

Your user account or Cloud Run workload calls the Google IAM signBlob API using roles/iam.serviceAccountTokenCreator. Google's managed key server signs the URL remotely—zero JSON private key files ever touch your hard drive.

⚠️ Approach B: Downloaded Service Account JSON Key (Local Lab / Legacy)

You export a physical .json key file containing an embedded -----BEGIN PRIVATE KEY----- RSA block. The CLI or Spring Boot JVM signs the URL locally in memory without making a network call to IAM.

3. Where Should the Service Account JSON Key Be Stored? (Production vs. Local Rules)

🚨 CRITICAL PRODUCTION WARNING (What is NOT a Good Practice):
1. NEVER store a Service Account JSON key inside src/main/resources/ or commit it to Git! Public and private Git repositories are continuously scanned; a leaked JSON key gives attackers persistent access until manually revoked.
2. NEVER bake a JSON key file inside a Docker image (COPY key.json /app/): Anyone who pulls the image from Artifact Registry can extract the layer and steal the private key.
3. Avoid long-lived JSON keys in production altogether: Exported JSON keys do not expire automatically. If your Organization Policy enforces iam.disableServiceAccountKeyCreation, generating JSON keys is blocked by design.

Module 2: Bucket CORS Configuration & Enterprise Signed URL Use Cases

Why JavaScript fetch() Fails Without CORS, Configuring cors.json, and Production Patterns

Cross-Origin Resource Sharing Preflight OPTIONS Browser Security

1. Why Do Browser JavaScript Clients Fail Without Bucket CORS?

When you paste a Signed URL into your browser's address bar or run curl, it works immediately. However, when a JavaScript frontend running on http://localhost:3000 or https://portal.mycompany.com calls fetch(signedUrl, { method: 'PUT', body: file }) to upload to https://soham-sg.storage.googleapis.com, the browser blocks the request with:

Access to fetch at 'https://soham-sg.storage.googleapis.com/...' from origin 'http://localhost:3000' has been blocked by CORS policy: Response to preflight request doesn't pass access control check: No 'Access-Control-Allow-Origin' header is present on the requested resource.

What happens under the hood: Because the origin (localhost:3000) differs from the GCS host (storage.googleapis.com) and uses a PUT verb or custom headers, the browser automatically sends an unauthenticated HTTP OPTIONS Preflight Request to your GCS bucket first. Your bucket must be configured with a CORS policy so GCS replies with the matching Access-Control-Allow-* headers.

2. Creating & Applying cors.json via gcloud CLI (Every Field Explained)

JSON — cors.json (PRODUCTION-READY BUCKET CORS POLICY) 
[
  {
    "origin": [
      "http://localhost:3000",
      "http://localhost:8080",
      "https://app.sohamsengupta.com"
    ],
    "method": [
      "GET",
      "PUT",
      "POST",
      "HEAD",
      "OPTIONS"
    ],
    "responseHeader": [
      "Content-Type",
      "Content-Length",
      "Content-Range",
      "Content-Disposition",
      "ETag",
      "x-goog-resumable",
      "x-goog-meta-uploaded-by"
    ],
    "maxAgeSeconds": 3600
  }
]
JSON Property Why It Is Needed & Production Guidance
"origin" Lists the exact frontend domains (scheme + host + port) allowed to make XHR/fetch calls to the bucket.
⚠️ Production Warning: Never set "origin": ["*"] on a bucket that accepts authenticated or signed uploads in production—always whitelist your exact frontend domains!
"method" HTTP verbs permitted from the browser: GET (downloads), PUT (direct uploads & resumable chunks), POST (initiating resumable sessions), HEAD (checking metadata), and OPTIONS (preflight).
"responseHeader" Headers the browser is allowed to send in preflighted requests or read from the response. Must include Content-Type (for PUT uploads), Content-Range (for resumable uploads/downloads), and x-goog-resumable.
"maxAgeSeconds" Tells the browser to cache the OPTIONS preflight response for 3600 seconds (1 hour) so it doesn't send a redundant preflight check on every single file chunk.
BASH — APPLY, INSPECT & TEST BUCKET CORS VIA GCLOUD CLI

package com.soham.cloud.signedurl; // Declares the Java package namespace for our microservice

import com.google.auth.oauth2.GoogleCredentials; // Base class representing Google OAuth2 credentials
import com.google.auth.oauth2.ServiceAccountCredentials; // Subclass holding the RSA private key needed to sign URLs
import com.google.cloud.storage.Storage; // Primary Google Cloud Storage client interface
import com.google.cloud.storage.StorageOptions; // Builder factory used to construct the Storage client
import org.springframework.beans.factory.annotation.Value; // Injects values from application.properties
import org.springframework.context.annotation.Bean; // Registers the returned object as a Spring-managed singleton bean
import org.springframework.context.annotation.Configuration; // Marks this class as a Spring configuration source

import java.io.FileInputStream; // Reads raw bytes from an external file path on the OS filesystem
import java.io.IOException; // Exception thrown if the credential file cannot be read

@Configuration // Tells Spring Boot to scan this class at startup and initialize @Bean definitions
public class GcsStorageConfig {

    @Value("${app.gcp.project-id}") // Injects 'ivory-link-511508-u3' from application.properties
    private String projectId;

    @Value("${app.gcs.signer-key-path:}") // Injects external JSON key path; defaults to empty string if omitted
    private String signerKeyPath;

    @Bean // Exposes a singleton 'Storage' client bean that can be @Autowired across our application
    public Storage googleCloudStorage() throws IOException {
        GoogleCredentials credentials; // Declares the credential object that will authenticate and sign requests

        // Checks if an explicit external JSON key file path was configured (Local Lab mode)
        if (signerKeyPath != null && !signerKeyPath.isBlank()) {
            // Opens a stream to the external JSON file (stored safely outside the repo) and parses its RSA private key
            try (FileInputStream keyStream = new FileInputStream(signerKeyPath)) {
                credentials = ServiceAccountCredentials.fromStream(keyStream);
            }
        } else {
            // PRODUCTION MODE: Automatically loads Application Default Credentials (ADC) from the Cloud Run/GKE Metadata Server
            credentials = GoogleCredentials.getApplicationDefault();
        }

        // Builds and returns the thread-safe Storage client bound to our project and signing credentials
        return StorageOptions.newBuilder()
                .setProjectId(projectId) // Binds the client to project 'ivory-link-511508-u3'
                .setCredentials(credentials) // Attaches the credentials capable of signing V4 URLs
                .build() // Finalizes the StorageOptions configuration object
                .getService(); // Instantiates and returns the active Storage service client
    }
}

2. Spring Boot Signed URL Microservice Controller (SignedUrlController.java)

This REST controller exposes two endpoints to your JavaScript frontend: GET /api/storage/sign-download (returns a 5-minute V4 GET URL) and POST /api/storage/sign-upload (returns a 10-minute V4 PUT URL locked to the exact Content-Type):

JAVA — SignedUrlController.java (EVERY LINE EXPLAINED) 
package com.soham.cloud.signedurl; // Package declaration

import com.google.cloud.storage.BlobId; // Composite identifier holding (bucketName, objectName)
import com.google.cloud.storage.BlobInfo; // Metadata wrapper around BlobId (holds Content-Type, headers)
import com.google.cloud.storage.HttpMethod; // Enum representing HTTP verbs (GET, PUT, POST, DELETE)
import com.google.cloud.storage.Storage; // The GCS client bean configured in GcsStorageConfig
import org.springframework.beans.factory.annotation.Value; // Reads properties from application.properties
import org.springframework.http.ResponseEntity; // Wraps HTTP status codes and JSON response bodies
import org.springframework.web.bind.annotation.*; // Provides @RestController, @GetMapping, @PostMapping, @CrossOrigin

import java.net.URL; // Standard Java URL object returned by storage.signUrl()
import java.util.Map; // Used to construct clean JSON key-value responses
import java.util.concurrent.TimeUnit; // Defines time units (MINUTES, SECONDS) for URL expiration

@RestController // Marks this class as a REST API controller that serializes responses to JSON automatically
@RequestMapping("/api/storage") // Base URI path for all endpoints in this controller
@CrossOrigin(origins = {"http://localhost:3000", "http://localhost:8080"}) // Allows our JS browser client to call this Spring Boot API
public class SignedUrlController {

    private final Storage storage; // Reference to our thread-safe Google Cloud Storage client bean

    @Value("${app.gcs.bucket-name}") // Injects 'soham-sg' from application.properties
    private String bucketName;

    // Constructor injection binds the Storage bean configured in GcsStorageConfig
    public SignedUrlController(Storage storage) {
        this.storage = storage; // Assigns injected bean to the final field
    }

    /**
     * ENDPOINT 1: Generate a V4 Signed URL for DOWNLOADING an existing private object
     * Example Call: GET http://localhost:8080/api/storage/sign-download?fileName=sample-text.txt
     */
    @GetMapping("/sign-download") // Maps HTTP GET requests on /api/storage/sign-download
    public ResponseEntity<Map<String, String>> generateDownloadSignedUrl(
            @RequestParam("fileName") String fileName) { // Extracts the 'fileName' query parameter from the request

        // Creates the unique pointer to 'gs://soham-sg/'
        BlobId blobId = BlobId.of(bucketName, fileName);

        // Wraps the BlobId in a BlobInfo metadata object required by the signUrl method
        BlobInfo blobInfo = BlobInfo.newBuilder(blobId).build();

        // Cryptographically signs the URL using the Service Account's private key (GOOG4-RSA-SHA256)
        URL signedGetUrl = storage.signUrl(
                blobInfo, // The target bucket and object to sign
                5, // Duration value: valid for 5 minutes (300 seconds)
                TimeUnit.MINUTES, // Unit of time for the duration parameter
                Storage.SignUrlOption.withV4Signature(), // Enforces Google's modern V4 signing algorithm
                Storage.SignUrlOption.httpMethod(HttpMethod.GET) // Locks the signature strictly to HTTP GET requests
        );

        // Returns HTTP 200 OK with a JSON payload containing the signed URL and metadata
        return ResponseEntity.ok(Map.of(
                "fileName", fileName, // Echoes back the requested file name
                "httpMethod", "GET", // Indicates the client must use HTTP GET
                "expiresInSeconds", "300", // Informs the client of the 5-minute TTL
                "signedUrl", signedGetUrl.toString() // Converts the signed URL to a String for the browser
        ));
    }

    /**
     * ENDPOINT 2: Generate a V4 Signed URL for UPLOADING a file directly from the browser
     * Example Call: POST http://localhost:8080/api/storage/sign-upload?fileName=report.pdf&contentType=application/pdf
     */
    @PostMapping("/sign-upload") // Maps HTTP POST requests on /api/storage/sign-upload
    public ResponseEntity<Map<String, String>> generateUploadSignedUrl(
            @RequestParam("fileName") String fileName, // Target object name to create inside the bucket
            @RequestParam("contentType") String contentType) { // MIME type of the file the browser wants to upload

        // Creates the unique identifier for the new object inside 'gs://soham-sg'
        BlobId blobId = BlobId.of(bucketName, fileName);

        // Builds the BlobInfo and explicitly sets the expected Content-Type (e.g., text/plain or image/png)
        BlobInfo blobInfo = BlobInfo.newBuilder(blobId)
                .setContentType(contentType) // Binds the MIME type to the object definition
                .build();

        // Signs a PUT URL that mathematically locks in the Content-Type header!
        URL signedPutUrl = storage.signUrl(
                blobInfo, // Target object metadata
                10, // Valid for 10 minutes
                TimeUnit.MINUTES, // Time unit
                Storage.SignUrlOption.withV4Signature(), // Uses V4 RSA-SHA256 signing
                Storage.SignUrlOption.httpMethod(HttpMethod.PUT), // Locks the URL strictly to HTTP PUT uploads
                Storage.SignUrlOption.withContentType() // CRITICAL: Forces the browser to send the exact matching Content-Type header!
        );

        // Returns HTTP 200 OK with the signed PUT URL and required Content-Type header
        return ResponseEntity.ok(Map.of(
                "fileName", fileName, // Target object key
                "httpMethod", "PUT", // Browser must execute fetch(url, { method: 'PUT' })
                "requiredContentType", contentType, // Browser must include Header 'Content-Type: '
                "signedUrl", signedPutUrl.toString() // The complete V4 signed upload URL
        ));
    }
}

3. JavaScript Browser Client (Upload & Download via Signed URLs — Every Line Explained)

Once your bucket has cors.json applied (from Tab 2) and your Spring Boot microservice is running, a browser client can upload and download files directly to/from GCS using standard fetch() calls:

JAVASCRIPT — browser-gcs-client.js (EVERY LINE EXPLAINED) 
// Base URL of our Spring Boot Microservice API
const SPRING_API_BASE = "http://localhost:8080/api/storage";

/**
 * 1. DIRECT BROWSER UPLOAD TO GCS USING A SPRING BOOT V4 SIGNED PUT URL
 * @param {File} fileInputObj - The File object selected from <input type="file">
 */
async function uploadFileViaSignedUrl(fileInputObj) {
    // Extract the file's name (e.g., "notes.txt") and MIME type (e.g., "text/plain")
    const fileName = encodeURIComponent(fileInputObj.name);
    const contentType = encodeURIComponent(fileInputObj.type || "application/octet-stream");

    // STEP A: Ask our Spring Boot microservice to generate a 10-minute V4 Signed PUT URL
    const tokenResponse = await fetch(
        `${SPRING_API_BASE}/sign-upload?fileName=${fileName}&contentType=${contentType}`,
        { method: "POST" } // Calls our @PostMapping("/sign-upload") endpoint
    );

    // Parse the JSON response returned by Spring Boot ({ signedUrl, requiredContentType, ... })
    const { signedUrl, requiredContentType } = await tokenResponse.json();

    // STEP B: Upload the raw file bytes DIRECTLY from the browser to Google Cloud Storage!
    // Notice this request goes straight to https://soham-sg.storage.googleapis.com, bypassing Spring Boot!
    const gcsUploadResponse = await fetch(signedUrl, {
        method: "PUT", // Must match HttpMethod.PUT signed by Spring Boot
        headers: {
            // CRITICAL: Must match the exact Content-Type locked via SignUrlOption.withContentType()
            "Content-Type": requiredContentType
        },
        body: fileInputObj // Streams the raw binary File/Blob directly over HTTPS to GCS
    });

    // Verify GCS returned HTTP 200 OK
    if (!gcsUploadResponse.ok) {
        throw new Error(`GCS Upload failed with status: ${gcsUploadResponse.status}`);
    }
    console.log("File uploaded directly to GCS bucket successfully!");
}

/**
 * 2. DIRECT BROWSER DOWNLOAD FROM GCS USING A SPRING BOOT V4 SIGNED GET URL
 * @param {string} targetFileName - Name of the private object in GCS (e.g., "sample-text.txt")
 */
async function downloadFileViaSignedUrl(targetFileName) {
    // STEP A: Request a 5-minute V4 Signed GET URL from our Spring Boot microservice
    const apiRes = await fetch(
        `${SPRING_API_BASE}/sign-download?fileName=${encodeURIComponent(targetFileName)}`,
        { method: "GET" } // Calls @GetMapping("/sign-download")
    );

    // Extract the temporary signedUrl string from the Spring Boot JSON response
    const { signedUrl } = await apiRes.json();

    // STEP B: Fetch the private object's content directly from Google Cloud Storage (CORS enabled)
    const gcsDownloadRes = await fetch(signedUrl, { method: "GET" });

    // Read the downloaded payload (or use .blob() for binary images/PDFs)
    const fileText = await gcsDownloadRes.text();
    console.log("Downloaded content from GCS:", fileText);
    return fileText;
}

Module 4: Resumable Uploads & Downloads — GCS vs. Spring Boot Responsibility

Who Manages Chunking, Session State, Byte Offsets, and HTTP 308 / 206 Recovery?

Control Plane vs Data Plane HTTP 308 Resume Incomplete HTTP 206 Range Reads

1. Architectural Verdict: Is Resumable Transfer Managed by GCS or Spring Boot?

A frequent architectural question in cloud interviews and production design is: "When implementing resumable uploads or downloads, does Google Cloud Storage manage the resumption automatically, or must our Spring Boot API handle it explicitly?"

The answer lies in separating the Control Plane (Session Initiation) from the Data Plane (Byte Streaming & Offset Tracking):

Operation What Google Cloud Storage (GCS) Manages Natively What Your Spring Boot API Must Handle What the Client (Browser JS or Java SDK) Must Handle
1. Browser-to-GCS Resumable Upload
(Direct Client Upload)		 100% of Session State & Byte Tracking:
• Generates a unique upload_id Session URI valid for 7 days.
• Buffers incoming 256 KB-aligned chunks.
• Responds with HTTP 308 Resume Incomplete + Range: bytes=0-X when asked how many bytes succeeded.
• Finalizes the object atomically on the last byte.		 Control Plane Only (Zero Byte Handling!):
Spring Boot only initiates the session (either by signing a POST URL with header x-goog-resumable: start OR making a 1-line POST to GCS to obtain the Location Session URI) and returns that URI to the browser.		 Chunking & Retry Loop:
A standard browser <input type="file"> will not auto-resume on its own. Your JS code must slice the file (file.slice()), send PUT chunks with Content-Range headers, and query the Session URI on network failure.
2. Backend-to-GCS Resumable Upload
(Server-Side Upload)		 Same native 7-day upload_id session tracking and atomic commit on Google's storage servers. Use storage.writer(blobInfo) (WriteChannel):
Do not use storage.create(blobInfo, byte[]) (which is a one-shot non-resumable upload). Using WriteChannel automatically uses a GCS resumable session!		 The Google Cloud Java SDK WriteChannel automatically chunks data (default 16 MB, configurable in 256 KB multiples) and allows state capture via writer.capture().
3. Resumable Download
(Browser or Backend)		 100% Managed Natively via HTTP Range Headers:
Every GCS object and every standard GET V4 Signed URL natively supports Range: bytes=start-end and returns HTTP 206 Partial Content.		 Nothing extra!
A standard HttpMethod.GET V4 Signed URL generated by Spring Boot automatically supports byte-range resumption out of the box.		 If a download drops at byte 5,000,000, the client simply sends GET to the same Signed URL with header Range: bytes=5000000- (or uses ReadChannel.seek(5000000L) in Java).

2. Code Example: Spring Boot Resumable Session Initiator + Browser Chunked Resume

Notice how Spring Boot signs a POST URL with the mandatory x-goog-resumable: start extension header, and the browser uses the returned Location header (the Resumable Session URI) to upload chunks and recover from network drops:

JAVA — SPRING BOOT ENDPOINT TO SIGN A RESUMABLE UPLOAD INITIATION URL 
// Inside SignedUrlController.java:
@PostMapping("/sign-resumable-init") // Endpoint called once by the browser before starting a large upload
public ResponseEntity<Map<String, String>> signResumableInitiationUrl(
        @RequestParam("fileName") String fileName, // Target object name in gs://soham-sg
        @RequestParam("contentType") String contentType) { // MIME type of the large file

    // 1. Identify the target object in our bucket
    BlobInfo blobInfo = BlobInfo.newBuilder(BlobId.of(bucketName, fileName))
            .setContentType(contentType) // Binds the MIME type to the session
            .build();

    // 2. Define the mandatory GCS extension header that triggers a Resumable Upload Session
    Map<String, String> extHeaders = Map.of("x-goog-resumable", "start");

    // 3. Sign an HTTP POST URL locking in 'x-goog-resumable: start'
    URL signedInitUrl = storage.signUrl(
            blobInfo,
            15, // The client has 15 minutes to initiate the session (once initiated, the session URI lasts 7 days!)
            TimeUnit.MINUTES,
            Storage.SignUrlOption.withV4Signature(),
            Storage.SignUrlOption.httpMethod(HttpMethod.POST), // Resumable initiation MUST use HTTP POST
            Storage.SignUrlOption.withContentType(), // Locks Content-Type
            Storage.SignUrlOption.withExtHeaders(extHeaders) // Locks 'x-goog-resumable: start' into the signature
    );

    // 4. Return the signed initiation URL to the browser
    return ResponseEntity.ok(Map.of(
            "signedInitiationUrl", signedInitUrl.toString(),
            "requiredHeaderKey", "x-goog-resumable",
            "requiredHeaderValue", "start"
    ));
}

/**
 * PART A: Initiate Resumable Session, Upload in 256KB Chunks & Auto-Resume on Interruption
 */
async function resumableBrowserUpload(file, signedInitiationUrl) {
    // 1. Send an empty POST with 'x-goog-resumable: start' to get the 7-day GCS Session URI
    const initRes = await fetch(signedInitiationUrl, {
        method: "POST",
        headers: {
            "Content-Type": file.type, // Must match signed Content-Type
            "x-goog-resumable": "start" // Tells GCS to open a resumable session and return a 'Location' header
        }
    });

    // 2. Extract the unique Resumable Session URI from the HTTP 'Location' response header
    // (Note: Once you have this sessionUri, it already contains an embedded upload_id token!)
    const sessionUri = initRes.headers.get("Location");
    let offset = 0; // Tracks the current byte offset

    // 3. If recovering from a network drop, ask GCS how many bytes it already committed!
    const statusRes = await fetch(sessionUri, {
        method: "PUT",
        headers: { "Content-Range": `bytes */${file.size}` } // Queries GCS for current committed byte range
    });
    if (statusRes.status === 308) { // HTTP 308 = Resume Incomplete
        const rangeHeader = statusRes.headers.get("Range"); // e.g., "bytes=0-524287"
        if (rangeHeader) {
            offset = parseInt(rangeHeader.split("-")[1], 10) + 1; // Resume from the exact next byte!
        }
    }

    // 4. Stream remaining bytes from 'offset' to the end of the file
    const remainingBlob = file.slice(offset, file.size); // Slices only the unuploaded portion of the file
    const uploadRes = await fetch(sessionUri, {
        method: "PUT",
        headers: {
            "Content-Range": `bytes ${offset}-${file.size - 1}/${file.size}` // Informs GCS of the exact byte window
        },
        body: remainingBlob // Sends only the remaining bytes directly to GCS
    });
    console.log("Resumable upload finished with status:", uploadRes.status); // 200 OK or 201 Created
}

/**
 * PART B: Resumable Download from a Standard V4 GET Signed URL using HTTP Range Header
 */
async function resumePartialDownload(signedGetUrl, alreadyDownloadedBytes) {
    // GCS natively honors the 'Range' header on any GET Signed URL and returns HTTP 206 Partial Content!
    const response = await fetch(signedGetUrl, {
        method: "GET",
        headers: {
            "Range": `bytes=${alreadyDownloadedBytes}-` // Requests only bytes from alreadyDownloadedBytes to EOF
        }
    });
    console.log("HTTP Status (206 = Partial Content):", response.status);
    return await response.blob();
}

1. What Problem Do the Channel APIs Solve?

In naive Java and Spring Boot applications, developers frequently write storage.create(blobInfo, Files.readAllBytes(path)) or byte[] data = storage.readAllBytes(blobId). While this works for a 2 KB text file, it causes catastrophic production failures at scale:

💥 The Problem: Byte-Array Heap Exhaustion (OOM)

  • Memory Contiguity Limit: byte[] requires a single contiguous block of JVM Heap memory and is capped at Integer.MAX_VALUE (~2.14 GB).
  • Concurrent Crash on Small VMs: On a free-tier e2-micro VM (1 GB RAM) or a 512 MB Cloud Run container, if just two users upload or download a 300 MB video using byte[], the JVM immediately crashes with java.lang.OutOfMemoryError: Java heap space!
  • No Random Seeking or Pause/Resume: With readAllBytes(), reading the last 1 MB of a 10 GB log file forces you to download all 10 GB.

🚀 The Solution: Java NIO Channels (FileChannel + WriteChannel / ReadChannel)

  • Constant $O(1)$ Memory Footprint: A 50 GB file is streamed through a fixed 64 KB or 2 MB ByteBuffer. Your JVM heap usage stays flat at ~2 MB regardless of whether the file is 10 MB or 5 TB!
  • Off-Heap Direct Buffers: Using ByteBuffer.allocateDirect() with FileChannel avoids copying bytes between OS kernel memory and JVM heap memory.
  • Random-Access Cloud Seeking: ReadChannel.seek(offset) jumps directly to any byte offset in a GCS object over HTTP Range requests.
  • Serializable Checkpoints: WriteChannel.capture() captures the live resumable upload state so you can pause and resume across threads or JVM restarts.

2. Example 1: Constant-Memory Upload from Local FileChannel to GCS WriteChannel (Every Line Explained)

This service method transfers a multi-gigabyte file from local disk to Google Cloud Storage using java.nio.channels.FileChannel and com.google.cloud.WriteChannel with an off-heap direct ByteBuffer:

JAVA — FileChannelUploadService.java (EVERY LINE EXPLAINED) 
package com.soham.cloud.channels; // Package namespace

import com.google.cloud.WriteChannel; // GCS NIO WritableByteChannel that manages a resumable upload session
import com.google.cloud.storage.BlobId; // Identifies (bucketName, objectName)
import com.google.cloud.storage.BlobInfo; // Holds object metadata (Content-Type)
import com.google.cloud.storage.Storage; // Thread-safe GCS client interface
import org.springframework.stereotype.Service; // Registers this class as a Spring Service bean

import java.io.IOException; // Standard I/O exception
import java.nio.ByteBuffer; // Fixed-size NIO memory buffer used to shuttle bytes between channels
import java.nio.channels.FileChannel; // Java NIO channel for high-performance local disk file I/O
import java.nio.file.Path; // Represents a local OS file path
import java.nio.file.StandardOpenOption; // Specifies how the local file should be opened (READ, WRITE, CREATE)

@Service // Marks as a Spring-managed component
public class FileChannelUploadService {

    private final Storage storage; // Injected Google Cloud Storage client

    public FileChannelUploadService(Storage storage) {
        this.storage = storage; // Constructor injection
    }

    /**
     * Streams a large local file to GCS using FileChannel -> ByteBuffer -> WriteChannel
     */
    public long streamLocalFileToGcs(String bucketName, String objectName, Path localFilePath) throws IOException {
        // 1. Construct the target object identifier and metadata
        BlobId blobId = BlobId.of(bucketName, objectName);
        BlobInfo blobInfo = BlobInfo.newBuilder(blobId)
                .setContentType("application/octet-stream") // Binary stream MIME type
                .build();

        // 2. Open the local file as a Java NIO FileChannel in READ mode, and open a GCS WriteChannel
        // Both channels implement AutoCloseable, so try-with-resources guarantees they close cleanly!
        try (FileChannel localFileChannel = FileChannel.open(localFilePath, StandardOpenOption.READ);
             WriteChannel gcsWriteChannel = storage.writer(blobInfo)) { // Initiates a GCS resumable session under the hood

            // 3. Configure the GCS WriteChannel chunk size to 2 MB (must be a multiple of 256 KB)
            gcsWriteChannel.setChunkSize(2 * 1024 * 1024);

            // 4. Allocate a 64 KB off-heap Direct ByteBuffer (avoids extra copying between OS kernel and JVM heap)
            ByteBuffer buffer = ByteBuffer.allocateDirect(64 * 1024);

            long totalBytesTransferred = 0L; // Counter to track total uploaded bytes

            // 5. Read chunks from local FileChannel into the ByteBuffer until EOF (-1) is reached
            while (localFileChannel.read(buffer) != -1) {
                // Flip the buffer from 'write mode' (reading from disk) to 'read mode' (draining to GCS)
                buffer.flip();

                // Ensure all bytes currently in the buffer are drained into the GCS WriteChannel
                while (buffer.hasRemaining()) {
                    totalBytesTransferred += gcsWriteChannel.write(buffer); // Writes bytes to the GCS channel
                }

                // Clear the buffer (resets position to 0) so it can be reused for the next 64 KB disk read
                buffer.clear();
            }

            // When the try-with-resources block exits, gcsWriteChannel.close() is called automatically,
            // which flushes the final resumable chunk and atomically commits the object in GCS!
            return totalBytesTransferred;
        }
    }
}

3. Example 2: Random-Access Range Download & Pause/Resume with ReadChannel.seek() & RestorableState

Below we show how ReadChannel combines with FileChannel to resume a partial download from a specific byte offset without re-downloading earlier bytes, and how RestorableState<WriteChannel> checkpoints an upload:

JAVA — FileChannelRangeDownloadAndResume.java (EVERY LINE EXPLAINED) 
package com.soham.cloud.channels;

import com.google.cloud.ReadChannel; // GCS NIO ReadableByteChannel supporting random-access seek()
import com.google.cloud.RestorableState; // Serializable state snapshot of an active GCS channel
import com.google.cloud.WriteChannel; // GCS NIO WritableByteChannel
import com.google.cloud.storage.BlobId;
import com.google.cloud.storage.BlobInfo;
import com.google.cloud.storage.Storage;
import org.springframework.stereotype.Service;

import java.io.IOException;
import java.nio.ByteBuffer;
import java.nio.channels.FileChannel;
import java.nio.file.Path;
import java.nio.file.StandardOpenOption;

@Service
public class FileChannelRangeDownloadAndResume {

    private final Storage storage;

    public FileChannelRangeDownloadAndResume(Storage storage) {
        this.storage = storage;
    }

    /**
     * 1. RESUMABLE / PARTIAL RANGE DOWNLOAD USING ReadChannel.seek() + FileChannel.position()
     * If a 2 GB download crashed after writing 500 MB to disk, this resumes directly at byte 500 MB!
     */
    public long resumeDownloadToLocalFile(String bucketName, String objectName, Path localTargetFile) throws IOException {
        BlobId blobId = BlobId.of(bucketName, objectName); // Identifies the cloud object to download

        // Open the local file with CREATE and WRITE options so we can append at the existing byte length
        try (FileChannel localFileChannel = FileChannel.open(
                localTargetFile, StandardOpenOption.CREATE, StandardOpenOption.WRITE);
             ReadChannel gcsReadChannel = storage.reader(blobId)) { // Opens a lazy NIO read stream to GCS

            // Determine how many bytes already exist in the local partial file on disk
            long existingLocalBytes = localFileChannel.size();

            // Move the local FileChannel write pointer to the end of the already-downloaded bytes
            localFileChannel.position(existingLocalBytes);

            // CRITICAL: Instruct GCS ReadChannel to seek directly to that exact byte offset in the cloud!
            // Under the hood, GCS ReadChannel sends an HTTP 'Range: bytes=-' request!
            gcsReadChannel.seek(existingLocalBytes);

            // Allocate a reusable 64 KB buffer to stream the remaining bytes
            ByteBuffer buffer = ByteBuffer.allocateDirect(64 * 1024);
            long newlyDownloadedBytes = 0L;

            // Stream from GCS ReadChannel straight into the local FileChannel
            while (gcsReadChannel.read(buffer) != -1) {
                buffer.flip(); // Prepare buffer for draining to disk
                while (buffer.hasRemaining()) {
                    newlyDownloadedBytes += localFileChannel.write(buffer); // Appends to local file
                }
                buffer.clear(); // Reset buffer for next network read
            }

            // Force OS filesystem buffers to flush to physical disk for durability
            localFileChannel.force(true);
            return newlyDownloadedBytes;
        }
    }

    /**
     * 2. CHECKPOINTING AN UPLOAD SESSION WITH RestorableState<WriteChannel>
     * Demonstrates how to pause a WriteChannel, serialize its state, and restore it after an interruption.
     */
    public RestorableState<WriteChannel> uploadChunkAndCaptureState(
            BlobInfo blobInfo, Path localPath, long chunkBytesToUpload) throws IOException {

        // Initiate a new resumable WriteChannel without auto-closing it (closing finalizes the object!)
        WriteChannel writer = storage.writer(blobInfo);
        writer.setChunkSize(256 * 1024); // Minimum 256 KB resumable chunk alignment

        try (FileChannel fileChannel = FileChannel.open(localPath, StandardOpenOption.READ)) {
            ByteBuffer buffer = ByteBuffer.allocate((int) chunkBytesToUpload); // Buffer for first chunk
            fileChannel.read(buffer); // Read first chunk from local disk
            buffer.flip(); // Switch buffer to read mode
            writer.write(buffer); // Transmit first chunk to GCS resumable session
        }

        // Capture and return the serializable state! You can save this object to disk/Redis and later call:
        // WriteChannel restoredWriter = savedState.restore(); to continue from the exact byte offset!
        return writer.capture();
    }
}
