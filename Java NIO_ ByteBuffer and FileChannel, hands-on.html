Java NIO tutorial

ByteBuffer and FileChannel: what problem do they solve?

Classic java.io streams give you one-way, front-to-back byte pipes. NIO gives you a typed in-memory block you control (ByteBuffer) and a file handle that can seek, lock, map and transfer (FileChannel). Play with the buffer first, then compare code, then see where streams simply cannot do the job.

1. ByteBuffer: a block with a cursor

A buffer has three numbers. capacity is the fixed size. position is the next index to read or write. limit is the first index you must not touch. Every bug people hit with ByteBuffer is a mistake about these two moving numbers. Click through a full write-then-read cycle.
